```kotlin

linesByName[station.name]  // 완전 일치

// neighbors: 같은 역명의 다른 lineId → isTransfer=true
```

## 3. P0 — 이수 / 총신대입구(이수)

### 3-1. 사실
| 항목 | 값 |
|---|---|
| 7호선 | `이수` (단독 명칭) |
| 4호선 | `총신대입구(이수)` |
| 좌표 거리 | **약 123m** (동일 환승역) |
| `linesServing("이수")` | `{1007}` only |
| `linesServing("총신대입구(이수)")` | `{1004}` only |
| 환승 엣지 | **없음** |

### 3-2. 경로 영향 (환승 페널티 6 기준 근사)

| 여정 | 별칭 없을 때 | 별칭 있을 때 | 비고 |
|---|---|---|---|
| 내방(7) → 사당(4) | cost≈18 (7→고속터→9→동작→4) | **cost≈8** (7→이수↔총신대→사당) | 최단 왜곡 |
| 용마산(7) → 사당(4) | ≈28 | ≈20 | |
| 석남 → 남태령 | ≈44 | ≈33 | |
| 장암 → 사당 | ≈32 (노원 환승) | 동일 가능 | 노원이 이미 4↔7 연결 |

네트워크는 노원·고속터미널 등으로 **연결은 유지**되지만,  
**4호선 남부 ↔ 7호선 남부** 최단이 심하게 우회한다.  
실사용자 체감: “한 정거장 환승”이 “9호선까지 돌아가는 경로”로 표시될 수 있음.

### 3-3. 수정 옵션

| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **D-1a 시드 표기 통일** | 4호선 역명을 `이수` 로 변경 또는 양측을 `총신대입구(이수)` 로 통일 | 코드 변경 최소 | API `statnNm`·사용자 검색 습관과 불일치 가능 |
| **D-1b 별칭 테이블 (권장)** | `StationAlias` 또는 `TransferLink(nameA, nameB)` 로 보행 환승 엣지 | 공식 표기 유지, 확장 가능 | `SubwayNetwork`·시드·테스트 수정 |
| **D-1c 표시명/정규화키 분리** | `Station.canonicalId` + `displayName` | 장기적으로 가장 깔끔 | 스키마·Room·UI 광범위 |

**권장: D-1b**  
예:

```kotlin
// SubwaySeed 또는 TransferLinks.kt
val WALK_TRANSFERS = listOf(
    "이수" to "총신대입구(이수)",
)
// SubwayNetwork.neighbors: name 의 alias 상대 노선도 isTransfer 로 연결
```

테스트 추가:
- `linesServing` 은 그대로 둬도 됨 (별칭은 neighbors/planner 레벨)  
- `JourneyPlanner(내방, 사당)` → legs 가 7→4 이수 환승 2구간  
- `SubwayNetworkTest` 에 별칭 환승 1건  

### 3-4. 유사 패턴 검색 결과
좌표 <300m + 이명(異名) 쌍: **위 1건만** 검출.  
괄호 base-name 만으로 깨진 multi-line 쌍: **없음** (온수·동작 등은 양 노선 표기 동일).

→ 현재 시드에서 **표기 불일치 환승 버그는 이수 단일 건이 전부**.

## 4. P1 — 1호선 분기 · 커버리지

### 4-1. 수록 범위 (의도적)

```
청량리 → … → 구로 → … → 인천   (경인선 38역)
lineId = "1001", lineName = "1호선", base statnId = 124
```

시드 주석 요지:
- 실시간 API 가 전 구간을 `subwayId=1001` 로 반환 → **lineId 항목은 하나**  
- 사용자 요청 구간(인천·부평 ↔ 서울역·청량리) 우선  
- **경부(수원·천안)·경원(의정부·소요산) 미포함**

### 4-2. 구조

| 구간 | 역 | 성격 |
|---|---|---|
| 트렁크 | 청량리…구로 (18역, 구로 포함) | 경인·경부 열차 공유 |
| 경인 전용 | 구일…인천 | 시드에 존재 |
| 경부 분기 | 가산디지털단지…수원… | **없음** |
| 경원 북부 | 회기…소요산 | **없음** |

### 4-3. 런타임 영향

| 시나리오 | 결과 |
|---|---|
| 출발/도착 = 수원·안양·광명·의정부 등 | 검색 목록에 없음 → 여정 불가 |
| 현황판(1호선) | 시드 밖 `statnId` 열차 드롭 (`BuildLineBoardUseCase` 주석과 동일) |
| 트렁크(예: 서울역)에서 탑승 매칭 | 경인행·경부행이 같은 출발역에 동시에 있으면 **Ambiguous** 또는 오매칭 |
| 경인 전용역(부평·주안 등) 탑승 | 매칭 안정 (주석대로) |
| 추적 중 boardedTrainNo 확정 후 | trainNo 기준이라 분기 진입 후에도 **API가 같은 trainNo를 주면** 추적은 가능. 다만 시드에 없는 역으로 가면 `graph.contains` 실패·보정 불가 |
| 경부행 열차를 경인 시드로 추적 | 구로 이후 역이 시드와 불일치 → **위치 소실(ACCEL 표시) 또는 Invalid** |

### 4-4. 수정 옵션

| 옵션 | 내용 | 언제 |
|---|---|---|
| **L1-keep** | 현행 유지 + UI에 “1호선(경인: 청량리–인천)” 명시 | MVP 사이드로드 |
| **L1-extend-linear** | 경부·경원을 한 줄에 억지 연결 | **비권장** — 위상 왜곡, 직전역 오판 |
| **L1-branches** | `LineTopology.BRANCHED` + 분기 그래프 (설계 1-6·작업12) | 1호선 전체 지원 시 |
| **L1-multi-seed** | 경인/경부/경원을 별 `lineId` 로 두고 API `1001` 매핑 테이블 | 매칭·현황판 복잡 |
| **L1-filter** | 매칭 시 `statnTnm`(종착역)으로 경인행만 후보 | 트렁크 오매칭 완화, **단기 권장** |

**단기 권장 조합:**  
1. UI 라벨로 커버리지 고지 (L1-keep)  
2. `MatchBoardedTrain` / 후보 리스트에 **종착역 필터 또는 표시** (L1-filter) — DTO에 `statnTnm` 이미 실측 존재·미매핑  
3. 중기: BRANCHED 토폴로지 (L1-branches)

### 4-5. DTO 확장 포인트 (1호선 매칭 품질)

`RealtimePositionDto` 실측 추가 필드(DESIGN 2-2a):
- `statnTid` / `statnTnm` — 종착역  
- 현재 Moshi 미매핑 → 도메인 미사용  

```text
TrainPosition + terminusName
MatchBoardedTrain: 경인 시드면 terminus ∈ {인천, 동인천, …} 또는 진행 방향 일치 강화
```

## 5. P2 — 허브 환승 공백 (미수록 노선)

수록 노선만으로 **연결성은 유지**되나, 실제 최단·상식 환승과 다름.

| 허브 | 시드 상태 | 실제 환승 | 사용자 영향 |
|---|---|---|---|
| 신도림 | 1호선 only | +2호선 | 2호선 여정 자체 불가 |
| 사당 | 4 only | +2 | 2호선 불가; 4–7은 이수 버그로 우회 |
| 건대입구 | 7 only | +2 | |
| 교대 | 3 only | +2 | |
| 시청 | 1 only | +2 | |
| 여의도 | 9 only | +5 | |
| 당산 | 9 only | +2 | |
| 합정 | 6 only | +2 | |
| 공덕 | 6 only | +5·경의 | |
| 김포공항 | 9 only | +5·공항 | |
| 종로3가 | 1·3 | +5 | 5호선 구간 불가 |
| 동대문역사문화공원 | 4 only | +2·5 | 이름 다른 동대문(1·4)과 별개 |
| 부평구청 | 7 only | 인천1 | |
| 석남 | 7 only | 인천2 | |

2호선 미수록이 허브 공백의 대부분.  
**수록 6노선 제품 범위 안**에서는 이수 P0만 즉시 버그.
